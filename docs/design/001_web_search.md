# #001 Web検索機能（Google Search Grounding）機能設計書

**作成日:** 2026年10月29日  
**最終更新日:** 2026年11月17日  
**ステータス:** 一部更新（#002, #012, #013 参照）  
**対象システム:** `src/gemio/core/agent.py`, `src/gemio/core/prompts.py`, `src/gemio/cli/main.py`, `src/gemio/cli/ui.py`  

### 【要約】
Gemini APIの Google Search Grounding を活用し、`/search`（または `/s`）コマンド明示時のみ安全に最新情報を検索する機能の設計書です。通常作業履歴（`chat_history`）からの機密情報隔離、連続深掘り検索セッション（`search_history`）、および出典ソース表示を定義します。

> **💡 現行仕様に関する注記:** `/search` 明示オプトイン・通常対話履歴の機密隔離・連続深掘り検索の基本方針は現在も有効ですが、検索結果の保持方式は [`002_search_material_integration.md`](./002_search_material_integration.md) で「作業前提資料」へ分離され、内部クラス構成（旧 `AIChatAgent` / 旧 `ui.py`）は [`012_ui_package_refactoring_for_textual.md`](./012_ui_package_refactoring_for_textual.md) および [`013_core_package_refactoring.md`](./013_core_package_refactoring.md)（`SearchAgent` 分離）で刷新されています（検索誘導プロンプトも `src/gemio/cli/prompts.py` へ分離済み）。現行仕様は [`manuals/07_ARCHITECTURE_REFERENCE.md`](../../manuals/07_ARCHITECTURE_REFERENCE.md) を参照してください。

## 1. 背景と目的

Gemioはローカルプロジェクトのソースコード解析、ファイル操作、自動テスト実行を行うAIコーディングエージェントです。  
一方で、急速に進化する言語仕様（例: Pythonの新機能）、外部ライブラリのメジャーアップデート（例: Pydantic v2、FastAPIの最新記法）、新しいツールの公式ドキュメントを参照する際、AIの事前学習知識だけでは古い情報や推測に基づいた回答（ハルシネーション）が発生するリスクがあります。

本機能では、Gemini APIの組み込み機能である **Google Search Grounding（検索グラウンディング）** を導入し、エージェントが最新の公式情報やWebドキュメントを参照できるようにします。

---

## 2. 基本方針と安全ガードレール

コーディングエージェントという性質上、**「意図しない外部Web検索の誤爆防止」** および **「ローカル操作機能の完全な安定性維持」** を最優先とします。

### ① 完全分離・明示的オプトイン方式
* 通常のプロンプト入力時（ファイル操作やAST解析、コード修正など）は、検索ツールは一切組み込みません。
* ユーザーが **`/search <調べたい内容>`** または **`/s <調べたい内容>`** と明示的にコマンドを入力した時のみ検索を実行します。

### ② API制約・ツール競合の完全排除
* Gemini APIには「Python関数（Function Calling）と Google Search Grounding を同一リクエストに同時指定できない」という制約が存在します。
* 検索実行時は「Google Search専用の設定（関数ツールを含まない）」でAPIを呼び出す分離リクエスト方式を採用することで、APIエラーやローカルツールとの競合リスクを原理的に排除します。

### ③ 検索意図の検知と誘導プロンプト（ハルシネーション防止）
* ユーザーがコマンドを付け忘れて通常のプロンプトで外部の最新仕様やドキュメントを尋ねた場合、AIが推測で回答することを禁止します。
* AIは検索が必要であると判断し、ユーザーに `/search` コマンドの使用を案内するようにシステムプロンプトで制御します。

### ④ 機密情報保護と深掘り検索（検索専用コンテキスト分離）
* プロジェクト作業途中に読み込んだソースコードや内部データ、秘密トークンが検索クエリ生成コンテキストとして外部（Google 検索エンジン）に送信されないよう、検索API呼び出し時は通常の作業履歴（`chat_history`）を完全に分離します。
* 独立した `search_history` を保持することで、ユーザーが「検索結果を見てさらに深掘り検索を行う（連続検索）」シナリオに対応し、直前の検索対話の文脈を引き継ぎます。
* 通常プロンプトが実行された際、または明示的なオプション（`-n` / `--new`）が指定された際に `search_history` は自動リセットされます。
* 検索結果（一連の検索プロンプトと回答）は全体の対話履歴（`chat_history`）にも反映されるため、直後の通常作業（例:「先ほど検索した仕様に従って〇〇モジュールを実装して」）で最新知識をそのまま活用できます。

### ⑤ 参照元ソース（出典）の透明性
* 検索結果の回答には、Geminiが根拠として参照したWebページのタイトルとURL（`grounding_metadata`）を抽出し、リッチに提示します。

## 3. アーキテクチャおよびモジュール詳細設計

### (1) エージェント層 (`src/gemio/core/agent.py`)

`AIChatAgent` クラスに、検索専用の処理メソッド `process_search_prompt` を追加します。

```python
def process_search_prompt(
    self,
    prompt: str,
    on_log_append: Callable[[str], None],
    new_session: bool = False,
) -> tuple[str, list[dict[str, str]]]:
    """
    Google Search Groundingを使用して最新情報を検索・取得し、回答を生成します。
    機密情報保護のため通常作業履歴は送信せず、連続検索のセッション履歴のみをAPIに送信します。

    Args:
        prompt: 検索・質問内容の文字列。
        on_log_append: ログ出力用コールバック関数。
        new_session: Trueの場合、直前の検索文脈をリセットして新規検索を開始する。

    Returns:
        tuple: (生成された回答テキスト, 参照元ソース情報のリスト [{"title": str, "url": str}])
    """
```

#### 内部処理フロー:
1. `new_session=True` の場合、`self.search_history` をクリア。
2. ユーザープロンプトを `/search <query>` 形式で `self.search_history`（`role="user"`）に追加。
3. 検索専用のConfigを作成:
   - `tools = [{"google_search": {}}]` （関数ツールは含めない）
   - `system_instruction = self.search_instruction` （検索専用インストラクションを適用）
   - `temperature = 0.0`
4. `self.client.models.generate_content(...)` を `contents=list(self.search_history)` で実行（通常作業の `chat_history` は送信しない）。
5. `response.candidates[0].grounding_metadata` から以下の情報を抽出:
   - 参照元Webサイトのタイトル (`grounding_chunks[].web.title`)
   - 参照元WebサイトのURL (`grounding_chunks[].web.uri`)
   - 実行された検索クエリ (`web_search_queries`)
6. 回答テキストを `self.search_history`（`role="model"`）に追加。
7. 回答テキストおよびユーザープロンプトを `self.chat_history` にも追加（後続作業用）。
8. 回答テキストおよび参照元リストを返却。

### (2) CLI・UI層 (`src/gemio/cli/main.py`, `src/gemio/cli/ui.py`)

#### ① コマンドハンドリング
対話入力ループ内で、入力テキストの先頭を判定します。

* **引数あり (`/search <query>` または `/s <query>`)**:
  - 先頭のコマンド部分を除去した検索クエリを抽出。
  - `agent.process_search_prompt(query, ...)` を呼び出し。
* **引数なし (`/search` または `/s` のみ)**:
  - 使い方ヘルプメッセージを表示:
    ```text
    [使い方] /search <調べたい内容> (または /s <調べたい内容>)
    オプション: -n または --new を指定すると直前の検索文脈をリセットして新規検索します。
    例: /search Python 3.13の新機能
        /search -n FastAPI ライフスパンハンドラー
    ※ 直前の検索結果を踏まえた追加質問・深掘り検索は、そのまま /search で続けて質問できます。
    ※ 通常のプロンプト入力ではWeb検索は実行されません。
    ```

#### ② リッチUI表示 (`rich`)
* 検索実行中は `rich.status.Status` によるスピナー表示:
  - 初回・新規検索時: `[bold green]🔍 Webを検索して最新情報を取得中...[/bold green]`
  - 連続深掘り検索時: `[bold green]🔍 直前の検索結果を踏まえて深掘り検索中...[/bold green]`
* 回答本文を `rich.markdown.Markdown` で描画。
* 参照元ソース（URLとタイトル）が存在する場合、`rich.panel.Panel` を用いてハイパーリンク付きで表示。

### (3) システムプロンプト（インストラクション）の設計 (`src/gemio/core/prompts.py`)

#### ① 通常時プロンプト (`DEFAULT_SYSTEM_INSTRUCTION`)
`src/gemio/core/prompts.py` の `DEFAULT_SYSTEM_INSTRUCTION` に以下のガードレール規定を追加します。

```text
【Web検索および外部の最新情報に関するルール】
- 通常のプロンプト処理ではWeb検索機能は無効化されており、ローカルファイルの操作ツール等のみが利用可能です。
- ユーザーからの入力が、外部ライブラリの最新仕様、最新バージョン、リリース情報、Web上の最新ドキュメントやニュースなど、明らかに「Web検索による最新情報」を期待していると判断できる場合は、自身の古い学習データや推測に基づいて回答してはいけません。
- そのような場合は作業を中断し、ユーザーに対して以下のように親切に案内してください：
  「外部の最新情報やWebドキュメントを参照するにはWeb検索が必要です。
   恐れ入りますが、コマンドの先頭に `/search` または `/s` を付けて再度送信してください。
   例: `/search <調べたい内容>`」
```

#### ② 検索実行時プロンプト (`DEFAULT_SEARCH_INSTRUCTION`)
検索実行時は「Web検索禁止・案内ルール」との衝突を防ぐため、検索専用のシステムプロンプトに切り替えて実行します。

```text
あなたはWeb検索機能を備えた優秀なAIアシスタントです。
Google検索ツールを活用し、最新の公式ドキュメント、リリース情報、言語・ライブラリの仕様などを調査して、正確で客観的な事実に基づいた回答を提供してください。

【基本ルール】
- 自身の古い学習データや推測に頼らず、Google検索によって得られた最新の事実・公式ドキュメントに基づいて回答してください。
- 根拠となる情報が見つからない場合は、曖昧な推測をせず、見つからなかった旨を正直に伝えてください。
- コード例を提示する場合は、公式が推奨する最新かつ安全な記法に従ってください。
- 本モードはWeb調査専用です。ローカルファイルの作成や変更は行いません。
```

Gemio    > 外部ライブラリの最新仕様や公式ドキュメントを参照するにはWeb検索が必要です。

Gemio    > ╭─ 🌐 参照元ソース (Sources) ─────────────────────────────────────────────╮
           │ • Lifespan Events - FastAPI (fastapi.tiangolo.com)                      │

## 5. テスト計画

自動テストおよび手動テストの両面から検証を行います。

### ① 自動テスト (`tests/test_agent_search.py`)
* **Config分離の検証**:
  - `process_search_prompt` 呼び出し時、渡される `tools` に `{"google_search": {}}` のみが設定され、関数ツールが含まれていないことをモックで検証。
* **出典メタデータ解析の検証**:
  - `grounding_metadata` のモックデータから、タイトルとURLが正しくディクショナリリストにパースされることを検証。
* **作業前提資料の保持検証**:
  - 検索プロンプトの送受信後、`search_materials` に資料が蓄積され、通常プロンプト時に先頭インジェクションされることを検証。

### ② 手動テスト (`manuals/06_MANUAL_TEST_GUIDELINE.md` に追加)
* Git ワークツリーを活用した隔離環境での動作確認:
  1. `/search` コマンドで最新の技術情報を検索し、参照元ソースが綺麗に表示されること。
  2. 引数なしで `/search` と打った場合に適切な案内が表示されること。
  3. コマンドなしで最新情報を尋ねた際に、AIが `/search` コマンドを促すこと。
  4. 検索直後に通常プロンプトでファイル操作を指示し、検索結果を踏まえたコードが生成されること。
