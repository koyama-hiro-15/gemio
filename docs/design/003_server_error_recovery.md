# #003 サーバーエラー・混雑時の回復と対話整合性維持 設計書

**作成日:** 2026年10月31日  
**最終更新日:** 2026年11月17日  
**ステータス:** 一部更新（#013 参照）  
**対象システム:** `src/gemio/core/agent.py`, `src/gemio/cli/main.py`  

### 【要約】
Gemini APIのサーバー混雑（503）やレート制限（429）、一時的な通信エラー発生時に指数バックオフで自動リトライを行うとともに、リトライ上限等で中断した際も実行済みツールの副作用と対話履歴を失わずに対話ターン（モデル発言補完）を正常終了させ、CLIプロセスのクラッシュを防ぐ仕様を定義します。

> **💡 現行仕様に関する注記:** 指数バックオフ自動リトライ、実行済みツール結果保持＋モデル中断発言補完、およびCLI例外保護の基本仕様は現在も有効ですが、内部実装（旧 `AIChatAgent._generate_content_with_retry`）は後続の [`013_core_package_refactoring.md`](./013_core_package_refactoring.md) にて `GenAIClient`・`ChatAgent`・`SearchAgent` へ分離・刷新されています。現行仕様は [`manuals/07_ARCHITECTURE_REFERENCE.md`](../../manuals/07_ARCHITECTURE_REFERENCE.md) を参照してください。

---

## 1. 改修の背景と目的

### (1) 現状の課題
1. **API呼び出し部分のエラーハンドリング不足:**
   `AIChatAgent._execute_agent_loop` および `process_search_prompt` 内で `self.client.models.generate_content(...)` を直接呼び出しているため、Gemini APIのサーバー混雑（HTTP 503）、レートリミット（HTTP 429）、一時的な内部エラー（HTTP 500/502/504）、ネットワークタイムアウト等が発生した際に例外が直接送出される。
2. **CLIプロセスのクラッシュ:**
   `src/gemio/cli/main.py` のメインループで大域的な例外ハンドリングが行われておらず、上記のエラーが発生するとCLIアプリケーション全体がクラッシュして終了する。
3. **対話履歴の不整合（状態汚染）とローカル環境との乖離リスク:**
   - ツール呼び出し（ファイル作成・修正等）を実行した後にAPIエラーが発生した場合、直前までのツール副作用（ローカルファイル等の変更）は既に確定している。
   - この状態で履歴をプロンプト入力時まで巻き戻すと、「ファイルは変更されているのにAIの記憶には無い」という状態の乖離が生じる。
   - 一方でツール戻り値のみを除去すると、Gemini APIのプロトコル（`function_call` には必ず `function_response` が対になる規約）に反し、次回リクエストで `400 Bad Request` が発生する。
   - さらに、ツール結果（`role="user"`）で止まった履歴に対してユーザーが新しい発言（`role="user"`）を送ると、`user` ロールが連続してAPIエラーとなる。

### (2) 改善の目的
- サーバー混雑や一時的エラーが発生しても**自動リトライ（指数バックオフ）**によって透過的に処理を復帰させる。
- リトライ上限到達などで中断した場合も、**既に実行されたツールの副作用と対話履歴を保持**し、ファイルの変更内容をAIの記憶から失わせない。
- エラー中断時に**対話区切り（モデル発言）を自動補完**することで、Gemini APIのターン制プロトコルを守り、中断後にユーザーが「続けて」と指示しても「別の作業をして」と指示しても安全に会話を継続できるようにする。
- CLI層に包括的な例外ハンドリング（セーフティネット）を設置し、アプリケーション全体の異常終了（クラッシュ）を完全に防止する。

## 2. 詳細仕様と設計

### (1) 指数バックオフ付き自動リトライ機構 (`src/gemio/core/agent.py`)

`AIChatAgent` にAPIリクエストを安全に行う共通メソッド `_generate_content_with_retry` を導入する。

```python
RETRYABLE_STATUS_CODES = {429, 500, 502, 503, 504}
MAX_RETRIES = 3
INITIAL_BACKOFF_SECONDS = 2.0
BACKOFF_FACTOR = 2.0
```

* **判定ロジック**:
  - `errors.APIError`（Google GenAI SDK固有の例外）の `code` 属性が `RETRYABLE_STATUS_CODES` に含まれる場合。
  - 一時的な通信切断やタイムアウト例外（`ConnectionError`, `TimeoutError` 等）。
  - クライアントエラー（400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found など）はリトライせず即時中断。
* **バックオフ制御**:
  - 試行1回目失敗: 2.0秒待機 ＋ ランダムジッター（±0.5秒）
  - 試行2回目失敗: 4.0秒待機 ＋ ランダムジッター
  - 試行3回目失敗: 8.0秒待機 ＋ ランダムジッター
* **ユーザー通知**:
  - 再試行待機時に `on_log_append` を呼び出し、「サーバー混雑または通信エラーを検知しました。{wait_time:.1f}秒後に再試行します (試行 {retry_count}/{max_retries})...」と状況を明示。

---

### (2) 対話整合性の担保とモデル発言自動補完 (`src/gemio/core/agent.py`)

自動リトライを上限まで試行しても回復しなかった場合、またはリトライ対象外のエラーが発生した場合の処理。

1. **履歴の保持（巻き戻し禁止）**:
   - すでに実行されたツール（ファイルの作成・修正、各種調査ツールなど）の戻り値（`function_response`）は `chat_history` から削除せずそのまま残す。
2. **モデル発言（中断マーカー）の自動補完**:
   - `chat_history` の末尾が `role="user"`（ツール実行結果、または初回プロンプト）の状態で中断した場合、末尾に以下の `role="model"` メッセージを追加して対話ターンを正常に閉じる。
   ```text
   申し訳ありません。サーバー混雑または通信エラーが発生したため、処理を一時中断しました。
   直前までに実行されたツール結果（ファイルの作成・修正など）は保持されています。
   作業を再開する場合は「続けてください」と入力するか、新しい指示を入力してください。
   ```
3. **効果**:
   - `function_call` → `function_response` → `model` の対話シーケンスが完成し、Gemini APIのターン規約を満たす。
   - 中断後にユーザーがどのようなプロンプトを入力しても（再開指示・方針転換のいずれでも）、`400 Bad Request` にならず自然に対話を継続可能。

---

### (3) Web検索機能の保護 (`process_search_prompt`)

- Web検索（Google Search Grounding）のAPI呼び出しも `_generate_content_with_retry` 経由で実行。
- 検索が失敗した場合、検索失敗のメッセージを返し、検索履歴（`search_history`）の不整合を回避する。

---

### (4) CLI層のセーフティネット (`src/gemio/cli/main.py`)

- `main.py` のユーザープロンプト処理およびWeb検索処理の実行ブロックを `try...except Exception as e:` で包括的に保護。
- 万が一予期せぬ例外が発生した場合でも、エラー内容をリッチな警告パネル（`Panel`）で分かりやすく表示し、CLIプロセスを終了させずに次のプロンプト入力待ちへ復帰する。

## 3. テスト計画

1. **自動リトライテスト**:
   - API呼び出しが 503 エラーを返し、2回目の試行で成功するケースの単体テスト（リトライが機能しログが出力されることの検証）。
2. **リトライ上限到達および対話整合性テスト**:
   - 連続して 503 エラーが発生しリトライ上限に達した際、例外でクラッシュせず、履歴末尾にモデルの中断発言が追加されることの検証。
   - ツール実行直後にエラーになった場合、ツール実行結果が履歴に維持され、その後にモデル発言が補完されることの検証。
   - 中断後に新しいプロンプトを送信してもロールの不整合が発生しないことの検証。
3. **既存回帰テスト**:
   - `pytest` を実行し、既存のテストがすべて合格することを確認。
