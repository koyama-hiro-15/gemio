# 📄 設計書・技術ドキュメント運用ルール

**作成日:** 2026年10月31日  
**最終更新日:** 2026年10月31日  
**ステータス:** 運用中  
**対象範囲:** `docs/` およびプロジェクト内のすべての設計書・技術仕様メモ  

### 【要約】
本プロジェクトにおける設計書・技術ドキュメントの作成および更新時における必須記載事項（日付、要約、ステータス、更新履歴）の標準ルールとテンプレートを定めます。

---

## 1. 基本方針

設計書や技術仕様書は、システムの現状（As-Is）や目指す仕様（To-Be）、実装の意図を正確に共有するための重要な資産です。
ドキュメントの陳腐化や「いつ作成・変更されたのか」「何のための設計書か」が分からなくなる事態を防ぐため、**新規作成時および更新時には必ず日付と要約を明記すること**を義務付けます。

---

## 2. 必須記載ルール

設計書を作成・更新する際は、**ドキュメントのタイトル直下（上部）**に以下のメタデータおよび要約を必ず記載してください。

### 2.1 新規作成時の必須項目
1. **作成日**: `YYYY年MM月DD日` 形式で作成日付を明記する。
2. **ステータス**: `ドラフト` / `レビュー待ち` / `設計完了` / `実装中` / `実装完了` などの進行状況。
3. **対象システム / モジュール**: 影響を受けるファイルパスやコンポーネント。
4. **【要約】(Summary)**: その設計書の目的、解決する課題、提案する仕様の要点を2〜4行程度で端的に記述する。

### 2.2 更新時の必須項目
既存の設計書に変更を加えた場合は、以下の対応を必ず行います。
1. **最終更新日の更新**: タイトル直下の `最終更新日` を当日の日付に更新する。
2. **要約の同期**: 仕様変更に応じて【要約】の内容を最新化する。
3. **変更履歴（Changelog）の追記**: 変更内容が多岐にわたる場合は、ドキュメントの末尾または要約直下に「更新日付」と「変更内容の要約」を追記する。

---

## 3. ヘッダー標準テンプレート

新規に設計書を作成する際は、以下のテンプレートをコピーしてドキュメントの先頭に配置してください。

```markdown
# 〇〇 機能設計書

**作成日:** YYYY年MM月DD日  
**最終更新日:** YYYY年MM月DD日  
**ステータス:** 設計完了（実装準備中）  
**対象システム:** `src/...`  

### 【要約】
（ここに本設計書の目的、対象機能、主な仕様や解決する課題の要約を2〜4行程度で記載してください）

---
```

---

## 4. 変更履歴セクションの記載例（任意・推奨）

仕様の追加や大きな変更を重ねるドキュメントには、末尾に以下のような変更履歴テーブルまたはリストを設けることを推奨します。

```markdown
## 更新履歴

| 日付 | 更新者 | ステータス | 変更内容の要約 |
| :--- | :--- | :--- | :--- |
| 2026-10-31 | AI Agent | 実装完了 | 初版作成および実装の完了を反映 |
```
