## 1. Gemioとは（概要と特徴）

**Gemio** は、日常のドキュメント作成・データ整理・Webリサーチといった一般的な業務から、多言語プログラミング・テスト検証・デバッグといった本格的なソフトウェア開発までを安全かつ強力にサポートする対話型AIエージェントです。

### 主な特徴
* **用途に応じた2層モード設計**:
  * **基本モード（デフォルト）**: Dockerなどの専門ツールを準備することなく、誰でもすぐに利用可能。指定したフォルダ内でのファイル読み書き・探索・Python静的構文チェックのみを行い、パソコンのシステム環境を決して壊さない安全な設計です。
  * **開発者モード（`--dev`）**: 隔離されたDockerサンドボックス（Dev Container / Dockerコンテナ）内でのみシェルコマンドを実行し、Python、TypeScript/Node.js、Go、Rust等のビルド・テスト実行・エラー修正までを自律的に行います。
* **作業内容と信頼度に応じた「3段階の承認モード」**:
  * すべての変更・コマンド実行を人間が確認する**通常承認モード**、ファイル作成・編集のみ自動承認して削除とコマンド実行は確認する**エディットモード**（`--edit` / `/edit`）、信頼できる自作プロジェクトで高速に自律作業させる**トラストモード**（`--trust` / `/trust`）を自在に切り替えられます。
* **強力な暴走防止機構と双方向コミュニケーション**:
  * 操作を拒否した後にAIが勝手に別の手段で変更を強行しようとした場合、**サーキットブレーカー**が作動して作業を自動停止します。また、仕様の曖昧さや判断に迷う点がある場合はAIから **`ask_user`** ツールで人間に質問・相談を行います。
* **機密情報を守るWeb検索連携**:
  * 作業中のローカルファイルや機密データを外部へ送信することなく、最新のWeb情報を検索して「作業前提資料」として活用できます。

## 2. 事前準備とセットアップ

### 2.1 必須環境（要求システム要件）
1. **Python 3.11 以上**（3.11 / 3.12 / 3.13）
2. **対応OS & ターミナルエミュレータ**:
   * **OS**: Windows 10 (22H2以降) / 11、macOS、Linux、WSL2
   * **ターミナル**: モダンな ANSI / 仮想ターミナル対応エミュレータ（推奨サイズ: **80列 × 24行 以上**）
     * **Windows**: Windows Terminal（推奨）、VS Code / Cursor 統合ターミナル、WezTerm 等（※旧来のレガシー `conhost.exe` 単体は非サポート）
     * **macOS / Linux / リモート**: Terminal.app、iTerm2、Ghostty、WezTerm、VS Code Remote / Dev Containers、対話型 SSH (`docker exec -it` 含む)
3. **Gemini APIキーの設定**:
   **ホストOS**（手元のPC）の環境変数 `GEMINI_API_KEY` にGoogle AI Studio等で取得したAPIキーを設定してください。

   ※セキュリティ保護のため、DockerコンテナやDev Containerの内部には環境変数としてAPIキーを設定しないことを推奨します（設定されている場合は、起動時や `/sandbox` 診断パネルで `🔴 危険` の強い警告が表示されます）。

   **Windows (PowerShell の場合):**
   ```powershell
   $env:GEMINI_API_KEY="あなたのAPIキー"
   ```

   **macOS / Linux / WSL2 (bash/zsh の場合):**
   ```bash
   export GEMINI_API_KEY="あなたのAPIキー"
   ```

### 2.2 開発者モード（`--dev`）を使う場合の追加環境
開発者モードでは、ホストOSを保護するため**コンテナ環境（Docker / Dev Containers）が必須**です。
* **Docker Desktop**（Windows / macOS）または **Docker Engine**（Linux）

## 3. 基本的な使い方（起動・入力・終了）

### 3.1 起動方法
```bash
# カレントディレクトリ（現在のフォルダ）を作業対象として起動
python -m gemio
# （pip install -e . でインストール済みの場合は `gemio` コマンドでも起動できます）

# 特定のフォルダを作業対象として指定して起動
python -m gemio /path/to/your_folder
```

### 3.2 Textual TUI の画面構成とキー操作
GemioはフルスクリーンTUI（Textual）で動作します。
* **上部ステータスヘッダー**: 対象プロジェクト名、動作モードバッジ（`STD` / `DEV:...`）、承認モードバッジ（`NORMAL` / `EDIT` / `TRUST`）、使用モデル、コンテキスト量（`Ctx`）と保持資料数（`M`）が常時表示されます（マウスクリックでも各設定・診断画面を開けます）。
* **中央対話タイムライン**:
  * **あなたの入力プロンプト**は Markdown 変換を行わず、コード断片や記号・インデントが**入力したままの生テキスト**で正確に表示されます。
  * **途中のツール呼び出しや思考ログ（Thinking）**は `▸ Tools (...) | Thinking (...)` にリアルタイムで格納・折りたたまれ、クリックや `Enter` でいつでも展開確認できます。
  * **Gemioの回答**はシンタックスハイライト付きの Markdown として描画され、各カードの `[Copy]` ボタンや `/cp`（`/copy`）コマンドでコピーできます（OSC 52 対応により SSH / Dev Container 内からもコピー可能）。
* **下部アクティビティバー & マルチライン入力欄**: 改行や折り返し行数に応じて3〜8行まで即座に自動伸縮し、入力欄に滞在したまま過去のタイムラインを自由にスクロール参照できます。

| 操作 | キー操作 | 説明 |
| :--- | :--- | :--- |
| **送信する（確定）** | **`[Ctrl+J]`** | 入力したプロンプトまたはコマンドを送信します。 |
| **改行する** | **`[Enter]`** | そのまま新しい行へ改行します。 |
| **入力欄を全消去する** | **`[F7]` ➔ `[Backspace]`** | 全テキストを選択して消去します。 |
| **元に戻す / やり直し** | **`[Ctrl+Z]` / `[Ctrl+Y]`** | 入力欄の編集操作を Undo / Redo します。 |
| **入力欄へフォーカス移動** | **`[F4]`** | タイムライン閲覧中などにプロンプト入力欄へフォーカスを戻します。 |
| **過去ログをスクロール** | **`[PageUp]` / `[PageDown]`** | 入力欄にフォーカスしたまま対話タイムラインを上下スクロールします。 |
| **実行中ターンの中断** | **`[Esc]`** *(AI思考・検索実行中)* | **アプリを終了せず**、現在のターンとサンドボックス子プロセスのみを停止して入力待ちへ戻ります。 |
| **テキストのコピー** | 各カードの **`[Copy]`** ボタン / `/cp` | 入力プロンプトやAI回答テキストをクリップボードへコピーします。 |
| **コマンドパレット** | **`[Ctrl+P]`** | 全コマンド・モデル切替・設定変更を検索して実行します。 |
| **クイック機能** | **`[F1]`**: ヘルプ / **`[F2]`**: モデル / **`[F3]`**: 承認切替 / **`[F4]`**: 入力欄 | ワンキーで主要モーダル・モード切替・フォーカス移動を実行します。 |
| **終了する** | **`[Ctrl+Q]`** または `/exit` (`exit`, `quit`) | Gemio TUI を安全に終了します。 |

## 4. 2つの動作モードの使い分け

### 4.1 基本モード（Standard Mode：一般作業向け・デフォルト）
オプションを付けずに起動した場合、常にこの**基本モード**で動作します。

```bash
python -m gemio ./my_documents
```

* **向いている用途**:
  * 企画書、レポート、マニュアル、メモなどの作成・要約・校正
  * フォルダ内のファイル整理、テキストの一括検索・置換
  * ブラウザ調査と作業前提資料（`/materials`）を活用した最新情報の調査と資料まとめ
  * 軽量なスクリプトやコードの作成・閲覧・Python静的構文チェック（`syntax_check`）
* **安全性の保証**:
  * シェルコマンドや外部プログラムの実行機能（`subprocess`）を一切持たないため、**パソコン内のシステムを壊したり、意図しないプログラムが勝手に実行されたりする心配がありません**。

---

### 4.2 開発者モード（Developer Mode：多言語開発・サンドボックス向け）
`--dev` オプションを明示的に指定した場合のみ、**開発者モード**で起動します。
基本モードの全ツールに加え、Dockerコンテナ内でシェルコマンドを実行する **`run_sandbox_command`** ツールが有効になります（詳細は [`02_DEVELOPER_MODE_MANUAL.md`](./02_DEVELOPER_MODE_MANUAL.md) を参照してください）。

#### スタイルA：ホストOS上から起動し、コンテナへコマンドを委譲する（最推奨）
Gemio本体はホストOS（手元のPC）で動かし、シェルコマンドの実行だけを稼働中のDockerコンテナ内で行わせる方法です。

```bash
# 接続先のDockerコンテナ名（またはID）を明示指定して起動
python -m gemio ./my_app --dev --container my-dev-container

# プロジェクトに対応する稼働中コンテナを自動検出して起動
python -m gemio ./my_app --dev
```

* **ホストOSのシェルを直接叩くことは絶対にありません**。
* APIキーはホストOS側のメモリにのみ存在し、コンテナ内には一切渡りません。また、コンテナを `--network none`（外部通信遮断）で起動していても完全に動作します。

#### スタイルB：Dev Containerの内部でGemioを起動する
VS Codeの「Dev Containers: Reopen in Container」等で開いたコンテナ内のターミナルから直接Gemioを起動する方法です。

```bash
python -m gemio --dev
```

* **コンテナ内でのAPIキー保護と起動時入力**:
  * コンテナ内起動時は、AIが環境変数や `/proc/*/environ` からAPIキーを読み取るリスクを防ぐため、**コンテナの環境変数（`devcontainer.json` 等）にはAPIキーを設定しない**でください（設定されている場合は起動直後の診断パネルで `🔴 危険` の強い警告が表示されます）。
  * コンテナ環境変数にAPIキーを設定せずに起動すると、**ホストOS側の環境変数からAPIキーをコピーするためのOS別コマンド案内パネル**が表示されます。
  * ホストOS（手元のPC）で別のターミナルを開き、案内されたコマンド（例: PowerShellなら `Set-Clipboard $env:GEMINI_API_KEY`、macOSなら `printf "%s" "$GEMINI_API_KEY"` | pbcopy 等）でAPIキーをコピーして貼り付けてください。
  * 入力したAPIキーは画面上で `****` としてマスク表示され、確認なしでそのままスムーズに起動します（コピーに使ったホスト側の別ターミナルは閉じて構いません）。

## 5. 安全機能と3段階の承認システム・双方向対話

### 5.1 承認確認画面の見方と4つの選択肢
承認確認が必要な操作（ファイルの作成・上書き・置換・削除やシェルコマンド実行）を行おうとする際、確認パネルが表示されます。

| 入力キー | アクション | 動作の説明 |
| :---: | :--- | :--- |
| **`y`** | **許可 (Yes)** | その操作の実行を許可し、作業を続行させます。 |
| **`n`** | **拒否 (No)** | その操作を拒否します。Gemioには「一度作業を止めてユーザーに意図を説明し、相談すること」という指示が返されます。 |
| **`a`** | **作業を強制中止 (Abort)** | **現在のGemioの思考・ツール実行ループをその場で即座に打ち切り**、あなたの次のプロンプト入力待ち状態へ戻します。 |
| **`k`** | **プロセス即時終了 (Kill)** | **緊急停止ボタン**です。実行中の子プロセスがあれば即座に強制キルし、Gemioプログラム自体を直ちに終了します。 |

---

### 5.2 サーキットブレーカー（承認拒否無視に対する自動強制中止）
承認確認で **`n`（拒否）** を選んだにもかかわらず、万が一AIが説明・相談（`ask_user` 呼び出し等）を行わずに**連続して別のファイル変更やコマンド実行を強行しようとした場合**、**「サーキットブレーカー（安全遮断器）」** が自動的に作動し、作業ループを強制停止します。

---

### 5.3 3段階の承認モード（通常承認モード / エディットモード / トラストモード）
作業内容やプロジェクトの信頼度に応じて、3段階の承認モードを自在に使い分けられます。

| 承認モード | 指定方法 | ファイル作成・編集・移動・コピー | ファイル削除 (`delete_path`) | シェルコマンド実行 (`run_sandbox_command`) |
| :--- | :--- | :---: | :---: | :---: |
| **🟢 通常承認モード** | デフォルト | 都度確認 | 都度確認 | 都度確認 |
| **🟡 エディットモード** | `--edit` / `/edit` | **自動承認** | 都度確認 | 都度確認 |
| **🔴 トラストモード** | `--trust` / `/trust` | **自動承認** | **自動承認** | **自動承認** |

* **エディットモード（`--edit` / `/edit`）**:
  * 「コードや文書の作成・編集はGitで差分確認できるためテンポよく自動で進めさせたいが、ファイルの削除やシェルコマンドの実行だけは事前に確認したい」という場合に最適です。
  * 起動時に `python -m gemio --dev --edit` を指定するか、対話中に `/edit`（戻すときは `/edit off`）と入力すると、確認プロンプトなしで即座に切り替わります。
  * ※エディットモード中に削除やコマンド実行を拒否（`n`）した際、AIが無断でファイル書き換え等を試みた場合もサーキットブレーカーにより遮断されます。
* **トラストモード（`--trust` / `/trust`）**:
  * 自分で作成した信頼できるプロジェクトにおいて、ファイル操作もテスト・ビルドのコマンド実行もすべて確認なしで高速に自律実行させたい場合に使用します（有効化時は事前同意確認が表示されます）。

### 5.4 AIからの質問・確認パネル（`ask_user`）と連続実行上限の確認
Gemioは推測で無理な作業を強行せず、必要に応じて人間に判断を仰ぎます。

* **AIからの確認・質問パネル（`ask_user`）**:
  * 要件の曖昧さ、複数の実装方針、作業環境の不足（未導入パッケージ等）、または操作拒否後の代替案について、「💬 Gemioからの確認・質問」パネルが表示されることがあります。
  * **選択肢がある場合**: `1`〜`N` の番号で選択、`0` で自由記述入力、そのまま任意の文章を直接入力、または `a`（`abort`）で作業を強制中止できます。
  * **選択肢がない場合**: 直接回答・指示を入力するか、`a` で作業を強制中止できます。
* **連続ツール呼び出し上限の確認（20回ごと）**:
  * 無限ループを防ぐため、1回の指示で連続20回ツールが呼び出されると一時停止し、「処理を継続（追加ループ）しますか？」と確認が表示されます。続行する場合は追加ループ回数（デフォルト `10` 回）を指定でき、中断を選んだ場合は安全に入力待ちへ戻ります。

### 5.5 常に保護される機密・重要領域
通常承認モード・エディットモード・トラストモードを問わず、うっかりミスによる事故を防ぐため以下の操作はシステム側で自動的にブロックされます。

1. **プロジェクトフォルダ外へのアクセス**: `../` などを使った対象フォルダ外への読み書きや、外部を指すシンボリックリンク操作。
2. **多言語・クラウドの機密ファイル・機密ディレクトリの読み書き・検索**:
   * `.env`, `.env.*`, `.envrc`, `.secrets`, `secrets.*`（※ただしテンプレート用の `.env.example`, `.env.sample`, `.env.template`, `.env.dist` は読み書き可能です）
   * 秘密鍵・証明書・キーストア・認証ディレクトリ（`.ssh/`, `.aws/`, `.gcloud/`, `.azure/`, `.kube/`, `.docker/`, `.gnupg/`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.ppk`, `*.keystore`, `*.jks`, `*.kdbx`, `id_rsa*`, `id_ed25519*` 等）
   * パッケージ・クラウド認証設定（`.npmrc`, `.yarnrc.yml`, `.pypirc`, `.netrc`, `.git-credentials`, `auth.json`, `master.key`, `credentials.toml`, `*credentials*.json`, `*service-account*.json`, `*.tfstate*`, `*.tfvars*`, `kubeconfig`）
   * ※これらを含むフォルダの丸ごと削除・移動もブロックされます。
3. **Git管理領域・サンドボックス設定・Gemio拡張領域・パッケージ生成領域の保護**:
   * `.git/` フォルダ内部への直接アクセス。
   * 既存の `.devcontainer/` 配下の設定変更・削除（※未作成時の新規作成のみ許可）。
   * `.gemio/` 配下（Skills やカスタムツール定義）および `*.egg-info/` 配下へのAIによる直接作成・変更・削除。

## 6. 対話中に使えるスラッシュコマンド一覧

### 6.1 ヘルプの表示 (`/help`)
```text
/help   (または /h, help, /info)
```

### 6.2 サンドボックス環境・マウント保護状態の診断 (`/sandbox`, `/status`)
開発者モード（`--dev`）の起動時に自動表示されるほか、対話中いつでもコンテナの設定（ネットワーク、実行ユーザー、機密環境変数の有無、リソース制限）およびワークスペース内のファイル・フォルダのアクセス権（`ls -la` 相当）と保護状態（`.env` が `/dev/null` でマスクされているか、`.git` が `ro` でマウントされているか等）を一覧表で診断・確認できます。
```text
/sandbox   (または /status, /container)
```

### 6.3 AIモデルの切り替え (`/model`)
`/model`（または `F2` キー）で開く選択モーダルでは、APIから利用可能なテキスト生成モデル一覧・Thinking対応可否（`[Think]`）・最大入力コンテキスト（`[1M]` 等）を動的に取得して表示します（`R` キーで最新一覧を再取得可能）。
```text
/model          # 選択モーダルから番号またはEnterで選択（APIカタログ自動取得）
/model neon     # 標準バランス型モデル (gemini-4-neon) へ即時切り替え
/model carbon   # 現最上位モデル (gemini-4-carbon) へ即時切り替え
/model hydrogen # 高速・軽量モデル (gemini-4-hydrogen) へ即時切り替え
/model 3.8      # Flash 3.8 (gemini-3.8-flash) へ即時切り替え
```

### 6.4 人間介在型 Web 検索支援 (`+WEB`/`-WEB`, `/web`) と作業前提資料 (`/materials`)
AIが外部の最新仕様や公式ドキュメントの確認を必要と判断した場合、ローカル非公開情報を除外した**調査目的・確認観点・推奨検索クエリ**を専用ダイアログ（`UserSearchModal`）で提示します。ユーザーは自身のブラウザで検索して必要な箇所を貼り付け（リアルタイムの**入力テキスト診断**で機密情報誤ペーストをブロック・不可視文字を無害化）、**「通常応答で送信」または「前提資料に追加し送信」**を選択できます（`TRUST` モードで停止させたくない場合は `-WEB` に切り替えられます）。
```text
/web on             # AIからの外部検索協力依頼（+WEB）を有効化（デフォルトON）
/web off            # AIからの外部検索協力依頼（-WEB）を無効化（ヘッダーバッジクリックでも切替可）
/materials          # 作業前提資料の一覧閲覧・手動追加・削除・全クリアを行う管理画面を開く（/mat も可）
/materials rm m1    # 指定した作業前提資料（例: m1 または番号）を1件削除
/materials clear    # 保持中のすべての作業前提資料を破棄
```

### 6.5 エディットモード・トラストモードの切り替え (`/edit`, `/trust`)
```text
/edit         # エディットモード（編集自動 / 削除・コマンド確認）のON/OFFをトグル切り替え
/edit on      # エディットモードを有効化（メッセージを表示して即時切替）
/edit off     # 通常承認モード（都度確認）に戻す

/trust        # トラストモードのON/OFFをトグル切り替え
/trust on     # トラストモードを有効化（事前同意確認あり）
/trust off    # 通常承認モード（都度確認）に戻す
```
*(※互換コマンドとして `/auto`, `/auto on`, `/auto off` も同様に動作します)*

### 6.6 トークン使用量・コンテキスト状態の診断 (`/tokens`, `/usage`)
現在のコンテキスト量（新セッションへ切り替えるかの判断目安：🟢快適 `50,000` 未満 / 🟡やや大 `50,000` 以上 / 🔴肥大化 `150,000` 以上）と、セッション開始からの累積トークン消費量（入力・出力・思考・キャッシュ・APIリクエスト回数）の内訳を表示します。
```text
/tokens   (または /usage, /token)
```

### 6.7 対話セッションのリセット・新規セッション開始 (`/clear`, `/reset`, `/new`)
CLIを終了・再起動することなく、現在の動作モード・承認モード・AIモデル設定を維持したまま、会話履歴・トークン統計・検索文脈・有効化中スキル等をリセットして新しい対話セッションを開始します。
```text
/clear         # 会話履歴とトークン統計をリセット（※ /materials で保持している作業前提資料は維持）
/clear --all   # 作業前提資料も含めて完全に初期状態へリセット（短縮: /clear -a）
```
*(※エイリアスとして `/reset`, `/new` も同様に利用可能です)*

### 6.8 回答コピー・コンテキスト要約圧縮・巻き戻し (`/copy`, `/compact`, `/rewind`)
```text
/copy         # 直近のAI回答テキストをクリップボードへコピー（短縮: /cp、各カードの [Copy] ボタンも可）
/compact      # 古い対話ターン群を構造化サマリへ要約圧縮し、直近2ターンを維持（引数で維持数を指定可）
/rewind       # 直近1ターンを対話履歴とタイムラインから巻き戻す（エイリアス: /undo、引数でターン数指定可）
```

### 6.9 セッションの終了 (`/exit`)
```text
/exit   (または exit, quit、キー: Ctrl+Q)
```

## 7. コマンドライン起動オプション一覧

```bash
python -m gemio [project_dir] [オプション]
# または: gemio [project_dir] [オプション]
```

| 引数 / オプション | 短縮形 | デフォルト値 | 説明 |
| :--- | :---: | :--- | :--- |
| **`project_dir`** | なし | `.` (カレント) | 作業対象とするプロジェクトフォルダのパス。 |
| **`--model <名前>`** | **`-m`** | `gemini-4-neon` | 起動時に使用するAIモデル名またはエイリアスを指定します。 |
| **`--dev`** | なし | 無効 (基本モード) | **開発者モード**を有効化し、Dockerサンドボックス内でのシェルコマンド実行を許可します。 |
| **`--container <名前>`** | なし | 自動検出 | ホストOSから `--dev` で起動する際、接続先のDockerコンテナ名またはIDを明示指定します。 |
| **`--edit`** | なし | 無効 (通常承認) | **エディットモード（ファイル作成・編集は自動承認、削除とコマンド実行は都度確認）**で起動します。 |
| **`--trust`** (互換: `--auto`) | なし | 無効 (通常承認) | 信頼済みプロジェクト向けの**トラストモード（自動承認）**で起動します。 |
| **`--dynamic-tools`** | なし | 無効 (全ツール有効) | **`[Experimental]`** 必要なツールセットのみをAIがオンデマンドで要求・有効化する動的ツールセット機能を有効化します。 |

## 8. プロジェクトごとの拡張（Skills & カスタムツール）

プロジェクト直下に `.gemio/` フォルダを作成することで、プロジェクト固有の専門ワークフローや独自ツールを追加できます。

* **Skills（専門手順書：`.gemio/skills/<スキル名>/SKILL.md`）**:
  コーディング規約、PR作成前チェック手順、ドキュメント作成ルールなどを Markdown で配置しておくと、関連する作業の開始時にGemioが必要なスキルだけをオンデマンドで読み込んで適用します。
* **カスタムツール（`.gemio/tools/*.py`）**:
  プロジェクト固有の計算・データ整形・検証用のPython関数をGemioのツールとして追加できます。
* **動的ツールセット（`--dynamic-tools`）**:
  ツール数が増えた際に、初期プロンプトのトークン消費を抑えつつ必要なツールセットだけを動的に有効化する実験的機能です。

👉 詳しい作成手順やテンプレートについては、専用マニュアル **[`06_SKILLS_AND_TOOLS_MANUAL.md`](./06_SKILLS_AND_TOOLS_MANUAL.md)** を参照してください。

## 9. トラブルシューティング・よくある質問（FAQ）

### Q1. `[Enter]` を押してもメッセージが送信されません。
* **A.** 複数行入力に対応しているため、`[Enter]` のみでは改行になります。送信するときは **`[Ctrl+J]`** を押すか、入力欄右側の `[Send]` ボタンを押してください。

### Q2. `--dev` を付けて起動したら「サンドボックス安全性検証エラー」が出て起動できません。
* **A.** 開発者モードは、安全のため生身のホストOS上ではシェルコマンドを実行しない設計になっています。Dockerで対象プロジェクトのコンテナを起動した状態で実行するか、`--container <コンテナ名>` を指定してください。また、`--privileged` や `--network host`、`docker.sock` マウントがあるコンテナは安全のため拒否されます。

### Q3. `.env` ファイルの中身をGemioに読ませたり編集させたりできますか？
* **A.** セキュリティ保護のため、`.env` や秘密鍵ファイルへのAIからのアクセスはブロックされています。設定のひな形をAIに作らせたい場合は **`.env.example`**（または `.env.sample`, `.env.template`, `.env.dist`）をご使用ください。

### Q4. Dev Containerの中で起動したとき、毎回APIキーを入力する必要がありますか？
* **A.** Dev Container内のターミナルで直接起動する（スタイルB）場合は、コンテナ内にAPIキーの痕跡を残さないため、Gemioを立ち上げる最初の1回だけ貼り付け入力が必要です（一度起動すれば `/exit` するまで対話を続けられます）。画面に表示されるOS別コマンドをホストOSの別ターミナルで実行すれば、数秒で簡単にコピペできます。なお、Dev Containerを起動した状態で**ホストOS側のターミナルから `python -m gemio . --dev` で起動する（スタイルA）**場合は、ホストOSのシステム環境変数がそのまま使われるため入力は不要です。
